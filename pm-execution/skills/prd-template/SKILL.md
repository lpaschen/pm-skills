# PRD Template Skill - Complete Content

This document provides a comprehensive framework for creating Product Requirements Documents, organized into nine main sections.

The **template structure** includes: Overview (problem statement, proposed solution, success metrics), Context & Background (why now, strategic alignment, user research), User Stories & Use Cases (formatted as "As a [user type], I want..."), Requirements (functional and non-functional), Design & UX, Technical Considerations, Implementation Plan (phased approach), Open Questions, and Appendix.

Key **writing guidelines** emphasize clarity and actionability: "Clear, concise, actionable" tone for engineers, designers, and stakeholders, with documents typically 3-6 pages for features or 8-12 for full products.

The guidance on quality PRDs recommends writing "from the user's perspective," including "specific success metrics," addressing edge cases, and linking to research. It advises against implementation details, ambiguous requirements, and skipping explanations of reasoning.

An example PRD for a "Multi-Channel Customer Support Dashboard" demonstrates proper formatting, showing how to articulate problems, propose solutions with quantified metrics, and structure user stories with acceptance criteria. The sample identifies that support agents waste "2.3 hours per day switching between tools" and outlines goals like reducing response time "from 4 hours to 1 hour."

The template emphasizes making requirements testable, including the "why" behind decisions, and updating documents as decisions evolve throughout development.
